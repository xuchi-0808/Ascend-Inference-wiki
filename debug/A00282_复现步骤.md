## 实验 1-3 综合结论（2026-06-17 最终版）

**根因**：`mc2_mask` 的 in-place 写入（`ascend_forward_context.py:185-186`）被 cudagraph capture，replay 时 slice 索引 `[:num_actual_tokens]` 保持 capture 时的值，不随实际 token 数更新 → 有效 token 被当 padding 丢弃 → MC2 dispatch 输出错乱。

### 为什么 GLM-5.1 / Kimi-K2.5 不受影响

三个模型**都走相同的 MC2 + cudagraph + mc2_mask 路径**，mask 问题对三者**同等生效**。但：

- **GLM/Kimi 有 shared experts**：最终输出 = `shared_output + fused_output`。shared expert 对所有 token 做 dense 计算，提供正确"基座信号"。即使 fused_output 部分错乱，shared output 的正确性足以让 accuracy 维持在阈值以上。
- **Qwen3-A22B 是 0 shared experts**：最终输出 = `fused_output`（纯 MC2 结果）。MC2 错乱 = 输出 100% 错乱 → accuracy 归零。

不是"GLM/Kimi 不受影响"，而是"GLM/Kimi 的 shared expert 补偿了 MC2 的错误"。

### 为什么 A3 不受影响

A3 的 `select_moe_comm_method`（`ascend_forward_context.py:288`）走 A3 分支，优先选 **FUSED_MC2**。FUSED_MC2 使用 `FusedMC2CommImpl` + `dispatch_ffn_combine` 算子，**完全不走 `TokenDispatcherWithMC2`，也不碰 `mc2_mask`**。是独立的代码路径。

### 实验矩阵

| # | 改动 | 改法 | 结果 | 含义 |
|---|------|------|------|------|
| 1 | ALLGATHER 绕开 MC2 | `ascend_forward_context.py:278` → `if False:` | ✅ | MC2 是根因 |
| 2 | 恢复 TP all-reduce | `fused_moe.py:282` 删 `MoECommType.MC2,` | ❌ | reduce 逻辑无关（MC2 输出是 token-split，TP all-reduce 会 sum 不同 token） |
| 3 | 关 cudagraph | `--compilation-config '{"cudagraph_mode": "NONE"}'` | ✅ | cudagraph 是必要条件 |

### 推理链

```text
7fd2cede (vllm MoE refactor: DefaultMoERunner → MoERunner)
  → MoERunner.forward() 改变了 forward scope（set_ascend_forward_context 进入 capture 范围）
    → mc2_mask 的 in-place 写入 mc2_mask[:num_actual_tokens]=True 被 capture
      → replay 时 num_actual_tokens 是 capture 时的值（不更新）
        → mask 标记错误：真实 token 被标 False（当 padding 丢弃）
          → MC2 dispatch 丢弃真实 token → combine 输出错乱
            → Qwen3 (0 shared) 全错；GLM/Kimi (有 shared) 被 shared expert 补偿
```

## 实验 5：修复 `mc2_mask` cudagraph capture（候选修复）

**修复思路**：`mc2_mask` 的 in-place 写入不能用动态 Python slice 索引（会被 capture 固化）。改用 **tensor 级别的比较操作**生成 mask，让 `num_actual_tokens` 作为 tensor 参与运算，cudagraph replay 时使用当前值。

### 改动（两节点都改）

**文件**：`vllm-ascend/vllm_ascend/ascend_forward_context.py`
**位置**：line 182-187

**修改前**：

```python
reserved_mc2_mask = get_mc2_mask()
if reserved_mc2_mask is not None:
    mc2_mask = reserved_mc2_mask[: forward_context.padded_num_tokens]
    mc2_mask[:num_actual_tokens] = True
    mc2_mask[num_actual_tokens:] = False
    forward_context.mc2_mask = mc2_mask
```

**修改后**：

```python
reserved_mc2_mask = get_mc2_mask()
if reserved_mc2_mask is not None:
    # A00282-fix: avoid in-place writes with dynamic Python slice indices.
    # Under cudagraph, mc2_mask[:num_actual_tokens]=True captures the
    # capture-time num_actual_tokens value; on replay the stale mask
    # misclassifies real tokens as padding → MC2 dispatch drops them.
    # Fix: build mask via tensor comparison so num_actual_tokens flows
    # through as a runtime value, not a baked-in constant.
    padded = forward_context.padded_num_tokens
    device = reserved_mc2_mask.device
    positions = torch.arange(padded, device=device)
    num_actual_tensor = torch.tensor(num_actual_tokens, device=device)
    forward_context.mc2_mask = positions < num_actual_tensor
```

### 原理

| 操作 | cudagraph 行为 | 问题？ |
|------|------|------|
| `mc2_mask[:N] = True`（旧） | capture 时 N 被固化，replay 用旧 N | **是** |
| `positions < num_actual_tensor`（新） | `num_actual_tensor` 是 device tensor，replay 时读当前值 | **否** |

`torch.arange` 和 `<` 都是 tensor 操作，被 capture 进图。但 `num_actual_tensor` 的值在每次 Python `forward()` 执行时重新创建（`torch.tensor(num_actual_tokens, ...)`），Python 层的 `num_actual_tokens` 变量每次取当前实际值。cudagraph replay 前会把输入 tensor 更新到当前值，mask 因此正确。
