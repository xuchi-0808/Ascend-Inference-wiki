## 定位进度

### 一致现象确认 ✅

两个 A2 fail log 均为 accuracy benchmark（aisbench）在 GSM8K-lite 数据集上报错：

```text
tools/aisbench.py:279: AssertionError: some aisbench cases failed
```

具体 error：

```text
Accuracy verification failed. The accuracy of ...gsm8k-lite is 0.0/3.12, which is not within 5 relative to baseline 96.
```

性能 benchmark（throughput）正常通过（2800 requests, 0 FAIL），说明模型能 serve 但输出内容质量严重退化。

### 已排除方向

| 方向 | 分析 | 结论 |
|---|---|---|
| A2 config yaml 变更 | git log 显示最后修改 2026-01-28，5/9→5/10 间无提交 | 排除 |
| vllm-ascend 代码 diff | 5/9 成功（`4b3a2af7`）到 5/10 首次失败（`ca4065f2`）仅 7 commits（UT/文档/Dockerfile） | 排除 |
| 通用代码 regression | 同一 commit `0b5223c5` 在 A3 通过测试（96.36%） | 排除 |
| 权重格式差异 | A2 和 A3 config 均使用 `Qwen/Qwen3-235B-A22B`，无 `--quantization` 参数 | 排除 |
| max-model-len 配置 | 成功轮（5/9）也是 `max-model-len=40960`，参数无变化 | 排除 |
| aisbench 判分逻辑 | aisbench.py 只是 wrapper，判分在 `ais_bench` pip 包内部，非判分 bug | 排除 |

### 2026-06-12 手动复现确认：并发推理乱码 🎯

在 A2 机器上手动复现确认：

- **单请求 curl**：模型回答正确 ✅
- **ais_bench 32 并发**：输出乱码，accuracy = 0% ❌
- **结论**：问题不在模型权重或单请求推理，而是**多并发场景下的 bug**
