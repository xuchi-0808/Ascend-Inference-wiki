# Wiki 信息架构设计

记录 Ascend Inference Wiki 的目录结构、分类逻辑、tag 体系与扩展性设计。目的：让未来维护者（含 AI Agent）理解架构意图，避免无序演化。

## 背景

本站定位为面向社区与 AI Agent 的昇腾大模型推理知识库。区别于官方文档，这里内容灵活、限制小，需要兼容多种形式与目的的文档：操作指南、参考手册、原理解析、设计提案、复盘博客，以及未来可能出现的形态。

本设计要解决三个核心问题：

1. **可发现性** —— 读者能快速找到所需内容
2. **低门槛** —— 贡献者能轻松判断新文档放哪
3. **可扩展** —— 未来新内容形态不需要推倒重来

## 目录主轴：读者意图

分类的本质是「读者从哪个入口找东西」。目录树只能挂一个主轴，选错主轴，一两年后必乱。

常见主轴对比：

| 主轴 | 问题 |
|---|---|
| 技术主题（DeepSeek / Qwen / 环境） | 一文档多主题打架；主题会过时（V3 之后有 V4） |
| 内容深度（入门 / 进阶） | 深度判断主观，不利于沉淀 |
| **读者意图（学 / 做 / 查 / 懂）** | **意图稳定，不随技术演进过时** |

选「读者意图」——十年前学编程的人和现在学推理的人，意图模式一样。主轴稳定，骨架就不会因技术演进而失效。这是 [Diátaxis](https://diataxis.fr/) 框架的核心思想（Django / NumPy / Cloudflare 采用）。

## 五大分类

| 分类 | 读者来 | 放什么 |
|---|---|---|
| 操作指南 | 做 | 跟着步骤完成任务 |
| 参考手册 | 查 | 查阅事实（API、参数、规格） |
| 原理解析 | 懂 | 理解机制与取舍 |
| 设计方案 | 议 | 方案 / RFC / 决策 |
| 博客 | 看 | 叙事 / 复盘 / 观点 |

判别口诀：**做、查、懂、议、看**。

> Tutorial（系统化课程）暂未上线；待上线时新增第六类即可——骨架已预留扩展，成本 O(1)。

## tag 双层模型

目录解决「放哪儿」（唯一归属），但无法表达「跟什么相关」（多对多）。例如「DSV3.2 双机精度回归」同时是 DeepSeek、双机、精度相关。若走目录，三个主题目录会打架。

解法：**目录 + tag 双层**。

- **目录**：按意图唯一归属（这篇放 `blog/`）
- **tag**：按主题多对多（挂 `DeepSeek` `双机` `精度`）

读者从任一主题入口都能找到它。

### categories 与 tags 的区别

- `categories`：blog 插件内部，按体裁分（复盘 / 开发笔记 / 版本解读）
- `tags`：全站，按技术主题分
- 一篇 postmortem 可同时有两者，从两个维度都能被找到

### 命名规范

- 专有名词 / 缩写用英文：`Qwen3` `MLA` `vllm-ascend`
- 通用概念 / 操作 / 场景用中文：`编译安装` `精度` `双机`
- 核心原则：**不要语义重复**，每个概念只用一个 tag
- 中英文都常用 → 中文；英文更常用 → 英文

## 扩展性设计

骨架能扛 2-3 年增长，演进路径都是无痛的增量调整：

| 未来变化 | 应对方式 | 迁移成本 |
|---|---|---|
| 某类内容变多 | 文件 → 目录 → 子目录深化 | 零（存量不动） |
| 出现全新意图 | 新增顶层目录 | O(1)，不波及存量 |
| 新维度冒出来（难度 / 受众 / 语言） | frontmatter 软字段 | 零结构改动 |

tag 是「逃生舱」：任何目录装不下的多对多关系，全走 tag，零目录改动。

## 软肋与治理

诚实承认架构的局限：

1. **跨类内容**：一篇「边操作边讲原理」的文章，归操作指南还是原理解析？硬规则是选主意图，用 tag 关联另一方面。
2. **系列内容跨类**：用 frontmatter `series:` 字段 + 索引页手工串联。
3. **类内涵漂移**：需定期 review，防止某类退化为大杂烩。
4. **纯社区 / 运营内容**：blog 或 about 兜底，不硬塞五类。

### 新类准入门槛

> 新增顶层分类前，必须证明现有 5 类都装不下这个内容。先尝试用 tag 或 frontmatter 字段解决，实在不行才加目录。

这能防止目录膨胀，让分类数长期收敛在 5-7 个。

## AI Agent 友好性

固定五大分类 + frontmatter 元数据 + 标签索引页。Agent 靠 nav 结构和 frontmatter 精准检索，不靠猜测。这也是本站区别于纯人工浏览文档站的设计考量。

## 技术实现

- [MkDocs Material](https://squidfunk.github.io/mkdocs-material/) 9.7+
- 插件：`tags`（跨分类主题索引）+ `blog`（归档 / 分类 / 作者卡片，阅读时间关闭因 CJK 不准）
- `meta` 插件必须在 `blog` 之前（顺序重要，否则默认值不生效）
- `tags.md` 用 `<!-- material/tags -->` 标记自动渲染索引
