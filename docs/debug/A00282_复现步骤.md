### 手动跑 Accuracy 测试（多并发复现乱码）

```bash

        stream=False,
        request_rate=0,
        use_timestamp=False,
        retry=2,
        api_key="",
        host_ip="80.48.37.120",
        host_port=8080,
        url="",

    )

# 3. 拷贝数据集配置文件（从已安装的 ais_bench 复制）
cp /usr/local/python3.12.13/lib/python3.12/site-packages/ais_bench/benchmark/configs/datasets/gsm8k/gsm8k_gen_0_shot_cot_chat_prompt.py \
   $BENCHMARK_HOME/ais_bench/benchmark/configs/datasets/gsm8k/

# 4. 拷贝 summarizer 配置
mkdir -p $BENCHMARK_HOME/ais_bench/benchmark/configs/summarizers

BENCHMARK_HOME="/tmp/aisbench_work" \
ais_bench --models vllm_api_general_chat_custom \
          --datasets gsm8k_gen_0_shot_cot_chat_prompt \
          --debug 2>&1 | tee /tmp/benchmark_acc.log
```

> 注意：第 3 步的 Python 版本路径（`python3.12.13`）以实际容器为准，可用 `ls /usr/local/` 确认。

**判读**：acc 恢复到 ~96% → 锁定 MC2 路径（嫌疑 npu_moe_gating_top_k / mc2_mask buffer）；仍 0% → 排除 MC2，聚焦路由/scheduler。

### E2：关 `--async-scheduling`（纯参数，无需改代码）

在两节点的 `vllm serve` 命令里**删掉** `--async-scheduling` 这一行，其余不变，重起跑 ais_bench。

**判读**：acc 恢复 → 锁定 async scheduling 与共享 buffer / DP sync 时序。

### E3：关 prefix-caching（纯参数，无需改代码）

在两节点的 `vllm serve` 命令里**加一行** `--no-enable-prefix-caching`（与 A3 配置对齐），其余不变，重起跑 ais_bench。

**判读**：acc 恢复 → 锁定 prefix-caching + scheduler 交互（`4d51588e2` 的 `remove_skipped_blocks`）。

### 汇总判读

| 结果组合 | 结论 | 下一步 |
|---------|------|--------|
| E1 恢复 | MC2 路径有问题 | 在 MC2 内部细分（mask buffer vs npu 算子） |
| E2 恢复（E1 不恢复） | async scheduling 时序 | 查 `disable_nccl_for_dp_synchronization` + mc2_mask |
| E3 恢复（E1/E2 不恢复） | prefix-caching + scheduler | 进入 vllm bisect，重点 `4d51588e2` |
| 都不恢复 | 路由/scheduler 通用问题 | 直接 Phase 4 vllm bisect，重点 `28c222157`/`fe85a92e8` |

推荐执行顺序：**E1 → E2 → E3**，再做 Phase 4 的 vllm bisect。
