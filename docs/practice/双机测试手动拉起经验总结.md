# 双机 nightly 测试手动拉起经验总结

## 背景

vllm-ascend 的 nightly CI 测试（`_e2e_nightly_multi_node.yaml`）基于 K8s LWS（LeaderWorkerSet）实现双机编排——pod 通过 `LWS_WORKER_INDEX` 和 `LWS_LEADER_ADDRESS` 环境变量自动识别角色、相互发现。在**非 K8s 裸机环境**下无法直接跑 `pytest` 拉起，需要手动启动 vllm serve。

本文档总结了从测试框架代码中提取出的手动拉起所需的全部信息。

---

## 1. 测试框架架构速览

测试流程涉及的四个主要组件：

```text
test_multi_node.py (pytest 入口)
  │
  ├─ MultiNodeConfigLoader.from_yaml()
  │    ├── 读取 Qwen3-235B-A22B.yaml
  │    ├── 调用 DistEnvBuilder.build() 注入网络环境变量
  │    └── 确定本机角色（master / worker）
  │
  ├─ ProxyLauncher（非 K8s 环境跳过代理）
  │
  ├─ RemoteOpenAIServer
  │    ├── _start_server() → subprocess.Popen(vllm serve, env=...)
  │    └── _wait_for_multiple_servers() → 轮询 /health
  │
  └─ run_aisbench_cases()
       └── AisbenchRunner → 调用 ais_bench CLI
```

关键源文件：

- `tests/e2e/nightly/multi_node/scripts/test_multi_node.py` — 测试入口
- `tests/e2e/nightly/multi_node/scripts/multi_node_config.py` — yaml 加载、`DistEnvBuilder`、`_resolve_cur_index`
- `tests/e2e/conftest.py` — `RemoteOpenAIServer`、`hang_until_terminated`
- `tools/aisbench.py` — 数据集准备、benchmark 执行
- `vllm/vllm/config/load.py` — `--safetensors-load-strategy` 定义

## 4. 数据集 & benchmark

### 数据集加载流程

`AisbenchRunner.__init__()` 的加载顺序（`tools/aisbench.py:63-67`）：

```python
self.dataset_path = aisbench_config.get("dataset_path_local")
if not self.dataset_path:
    self.dataset_path = maybe_download_from_modelscope(aisbench_config["dataset_path"])
```

1. 先查 `dataset_path_local`（yaml 中的本地路径）
2. 如果没设置，从 modelscope 下载

在 yaml 中配置 `dataset_path_local` 可以跳过 modelscope。

### BENCHMARK_HOME 的作用

`aisbench` 在运行时会把数据集从 `dataset_path_local` **拷贝**到 `$BENCHMARK_HOME/ais_bench/datasets/gsm8k/`。该路径需要可写。

如果已经将 GSM8K 直接放在了最终位置（如 `$BENCHMARK_HOME/ais_bench/datasets/gsm8k/`），则 `dataset_path_local` 可以和 `DATASET_DIR` 一致。**但如果两者完全相同**，`cp -r` 会报 `cannot copy a directory into itself`。此时需要临时设置一个不同的 `BENCHMARK_HOME` 来避免冲突，或者将 `dataset_path_local` 指向一个临时副本。

### benchmark 命令

benchmark 仍然通过 pytest 运行（因为需要框架解析 yaml、生成请求配置等）：

```bash
cd vllm-workspace_A00275/vllm-ascend
export BENCHMARK_HOME="/usr/local/python3.11.10/lib/python3.11/site-packages/"
export CONFIG_YAML_PATH="Qwen3-235B-A22B.yaml"
python -m pytest tests/e2e/nightly/multi_node/scripts/test_multi_node.py -x -s 2>&1 | tee /tmp/test_result.log
```

> 注意：benchmark 命令必须和 `vllm serve` 在**同一台机器（Node 0）**上运行，因为它需要访问 Node 0 的 HTTP 端口。

## 5. 常见坑

### Node 1 秒 pass，Node 0 engine init failed

现象：Node 1 的测试在十几秒内 1 passed，Node 0 报 `Engine core initialization failed. Failed core proc(s): {}`。

原因：Node 1 的 `hang_until_terminated()` 在没有等待 leader 就绪的情况下就退出了。Node 1 的 `vllm serve` 子进程也可能因为被抢卡而直接崩溃，但打屏日志被 pytest 捕获看不到。

排查：

1. 两台机器上分别执行 `npu-smi info` 确认 16 卡全部可用
2. Node 1 上单独跑 `vllm serve --headless ...`（不通过 pytest）看报错
3. 手动拉起 `vllm serve` 时不要同时跑 pytest

### vllm 版本号 dev 导致 import 错误

`vllm-ascend` 的 `patch_mla_prefill_backend.py:20` 中有一个版本守卫：

```python
if not vllm_version_is("0.20.2"):
    from vllm.v1.attention.backends.mla.prefill.base import MLAPrefillBackend
```

当从 git 源码用 `pip install -e .` 安装 vllm 时，`setuptools_scm` 可能因找不到 tag 而将版本号设为 `"dev"`，导致 `vllm_version_is("0.20.2")` 返回 False，从而尝试 import 一个不存在的模块。

解决方法：确保 vllm 版本正确。在 vllm 仓库中：

```bash
git checkout releases/v0.20.2
pip install -e .
```

如果 `v0.20.2` tag 存在，也可以用 `git checkout v0.20.2`。

### 权重加载慢

权重文件在 NFS 网络存储上时，默认的 lazy load 会导致按需随机读取，速度很慢。在 `vllm serve` 命令中加 `--safetensors-load-strategy prefetch` 可以将文件预读到 OS page cache，大幅加快加载速度。
